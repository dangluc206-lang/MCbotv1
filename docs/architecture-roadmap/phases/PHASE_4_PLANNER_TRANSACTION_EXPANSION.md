# Phase 4 — Planner and Transaction Expansion

## Outcome

Pure decision/replay và uncertain reconciliation trở thành reusable pattern cho storage/B5 và future economic mutations.

## Entry criteria

- P1 reliability gate.
- Capability/mode contract đủ ổn định.
- Server profile exposes required facts/revisions.

## Mandatory work packages

- WP-300 đến WP-303.

## Sequence

1. Standardize additive decision/result/replay envelope.
2. Extract common reconciliation semantics từ existing crafting evidence.
3. Build pure storage protection/sell planner.
4. Keep executor/action ownership unchanged initially.
5. Make B5 reference flow consume pure storage decision.
6. Add offline replay parity/fault fixtures.

## Storage/B5 invariants

- Fresh observation before plan/action.
- Smelting/conversion/sell order theo selected server/workflow contract.
- Sell only verified surplus; reserve floor policy explicit.
- Inflow after snapshot không kéo dài transaction tùy ý.
- Post-campaign protection gate trước next craft.
- Generation change discards decision/result.
- No movement/pathfinder in pure B5 mode.

## Required tests

- Pure deterministic planner fixtures.
- Snapshot freshness/completeness/generation rejection.
- Uncertain sell/craft no duplicate action.
- Reconcile succeeded/failed/unresolved.
- Reserve boundary/property tests.
- Planner purity architecture test.
- B5 trace/replay parity.

## Exit criteria

- Planner has no side effect imports.
- Executor follows decision/precondition/evidence contract.
- Storage/B5 regression behavior preserved.
- Shared reconciliation has real consumers, not cosmetic wrapper.

## Stop conditions

- Planner calls capability/server/timer.
- Retry click/sell after timeout without reconciliation.
- Generic engine hard-codes B1/B5.
- Large B5 rewrite without replay parity.

## Gate status — 2026-08-22

**PASS — MCbot 2.7.22.** WP-300 through WP-303 are complete. Pure planner, shared reconciliation, immutable storage planning and B5 reference conformance gates pass.
