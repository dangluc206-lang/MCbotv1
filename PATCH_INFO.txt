SCOPE
- Includes all 1.0.13 V5/full-optimization overlay work.
- Adds deterministic startup ordering:
  1) backend core starts and emits "MCbot Desktop backend started."
  2) Discord starts and must reach ClientReady/panel-ready barrier
  3) only then Minecraft runtimes are started
- Discord is removed from the backend-core LifecycleCoordinator and registered as a pre-runtime service barrier.
- Shutdown order is the reverse dependency chain: Minecraft runtimes -> Discord -> backend core.
- No fixed sleeps/delays were added.
- Existing DesktopController end-of-start duplicate backend log is naturally suppressed by DesktopLogPolicy because the early and late records use the same Desktop scope/message inside the repeat window.
