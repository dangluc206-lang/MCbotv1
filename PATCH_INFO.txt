RUNTIME-FAILURE CONTRACT
- runtime:failure is canonical for persistence and Discord reporting.
- Canonical diagnostic/details are detached and redacted before fan-out.
- Recorder uses arrival-time, race-safe dedupe; fixed-window repeat summaries;
  safe rotation/retention/quota; path containment; and oversized-record
  truncation.
- Connection failure aggregation keeps the richest diagnostic per physical
  bot/generation incident while legacy connection events remain available to
  existing consumers.
- Collector and Fishing own separate circuit breakers. Lifecycle cancellation
  and expected wait states do not consume failure budget. OPEN keeps the mode
  DEGRADED and only verified business success resets a failure streak.
- BotRegistry listener failures are sanitized/surfaced without rolling back a
  completed registry mutation or blocking later listeners.
- RuntimeFailurePublisher diagnostic-score fallback is deterministic and does
  not silently swallow serialization/scoring failures.

FISHING ARCHITECTURE
- FishingModeService is a bot-scoped orchestration/state-machine service and
  does not receive BotContext or raw Mineflayer objects.
- ConnectionStateView owns read-only connection/generation snapshots.
- ConnectionPacketObserver is the connection-scoped raw protocol owner.
- FishingMovementOperation owns movement sessions/control cleanup.
- FishingMovementProbeService owns bounded probe/calibration sequences.
- FishingPositionGuard owns immutable anchor/position validation.
- FishingWorldReadinessService owns bounded generation-aware world readiness.
- FishingRecoveryPolicy is pure recovery decision logic.
- FishingService owns raw fishing/rod/equip primitives and guard-aware cycle
  execution.
- AfkAreaService and Island teleport flow preserve generation/cancellation
  boundaries.
- ConnectionManager exposes backward-compatible
  requestReconnect(reason, { expectedGeneration }) so stale recovery cannot
  terminate a replacement client and mode/probe code never calls raw bot.end().
- /is and AFK teleport verification normalize connectionGeneration/generation,
  require exact current generation, and own waiter/timer/listener cleanup.
- Fishing connection events ignore stale/generation-less callbacks. Business
  cycle expectedGeneration is preserved through failure publish, cleanup and
  reconnect decisions so stale outcomes cannot mutate a replacement client.

COMMAND CANCELLATION / GENERATION CORRECTION
- CommandService forwards cancellationToken and optional expectedGeneration to
  CommandExecutor.
- CommandExecutor checks cancellation before throttle, uses cancellation-aware
  Timeout.delay(), then checks cancellation + exact connection generation +
  exact captured client immediately before bot.chat(). A cancelled or stale
  generation-sensitive command cannot be sent after throttle.
- IslandTeleportOperation owns an internal CancellationSource linked to its
  parent mode token. Teleport waiter timeout, stale generation, disconnect,
  cancellation or operation failure cancels the command branch immediately.
- Regression tests use real BotContext + CommandGuard + CommandExecutor +
  CommandService + IslandTeleportOperation with an active throttle and verify
  both old and replacement clients receive zero /is chat calls after cancel or
  generation replacement, even after waiting longer than the throttle.
